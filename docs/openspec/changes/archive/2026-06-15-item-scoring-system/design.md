## Context

The Wandering Soul and Memory Fragment systems require a mechanism to compare item values in order to generate fair and unfair trades at runtime. The existing `LLD-ITEMS-011` placeholder defines only the intent ("items SHALL have a tier value") but provides no formula, no values, and no relationship between items — it is entirely `[OPEN·MVP1]`.

A flat tier list would require manually categorising every item and would break when items naturally vary in power within the same design archetype (e.g. a 3-charge vs 8-charge version of the same weapon template). A compositional formula avoids both problems: scores emerge from properties the item already has, and normal/elite variants can be generated by adjusting a single stat.

This is a **spec-only change** — no code is modified. Implementation of the scoring system at runtime (trade generation, scenario selection) is a separate code change that will reference these specs.

## Goals / Non-Goals

**Goals:**
- Define a complete, compositional scoring formula for all items
- Establish two independent scales (Durability / Consumable) with reference points
- Formalise the `+1 target` scope modifier that was previously an undocumented per-item treatment
- Provide pre-playtest scores for all current items
- Update trade fairness language in HLD specs from tier-adjacency to score-tolerance
- Close `LLD-ITEMS-011` by superseding it with `lld-item-ranking`
- Correct three stale item definitions: Battered Sword charge count, Frost Shard pool placement, Cheap Flask effect

**Non-Goals:**
- Implementing trade generation logic in code
- Setting HP conversion amounts (depends on vessel HP pools; remains `[OPEN]`)
- Finalising Lucky Paw's score (depends on evasion % confirmation)
- Designing items for floors beyond Floor 3

## Decisions

**Two independent scales, not one unified tier.**
Durability items compete with each other for loot slots; consumables compete with each other. Mixing them into one scale would require an arbitrary conversion ratio between fundamentally different item types. Trades that cross the boundary (durability for consumable) are rare designer decisions, not generated ones — so no conversion ratio is needed at runtime either.

**Competent play as the scoring baseline, not perfect play.**
Perfect-play scores would make the formula useless for trade generation: a Brittle Charm paired with a physical weapon deals enormous expected damage, but the combo isn't guaranteed. Competent play assumes the player uses the item reasonably well but not optimally. This produces stable relative scores that survive run variation.

**Formalising `+1 target` as a scope tier.**
The Arc Wand arc was previously scored with an undocumented `×0.5` multiplier on the secondary hit. This turns out to follow the same frequency assumption as the AoE modifier: if encounters have a second enemy 50% of the time (the AoE discount from 2× to 1.5× encodes this), then a `+1 target` secondary hit also lands 50% of the time. Making this a named scope tier means future chain/arc items score consistently without per-item treatment.

**Charges multiplier is dampened, not linear.**
A 10-charge weapon is worth approximately 4.7× a 1-charge weapon, not 10×. Later charges carry compounding uncertainty — the item may be replaced, the run may end, the encounter may not require it. The dampened curve reflects this reliability discount.

**Manual scores for structural/passive items.**
Items whose value is not expressible as damage, healing, or status (Worn Map, Lucky Paw, Iron Pendant, Pocket of Sand, Ointment, Amethysts) receive manual scores benchmarked against the relevant scale reference point. Manual scores are marked as such in the item score table and are the most likely candidates for playtesting revision.

## Risks / Trade-offs

**Pre-playtest scores will drift.**
All scores are calculated from the formula but anchored to design-time assumptions about encounter frequency, optimal pairing, and omen timer distribution. Real play will reveal where these assumptions are wrong. The formula is the stable artefact; the specific numbers in the item score table are expected to change.
→ Mitigation: the item score table is in `lld-item-ranking`, not scattered across item definitions. One spec to update during playtesting.

**Manual scores are subjective.**
Lucky Paw, Worn Map, Iron Pendant, Pocket of Sand, and the Amethysts cannot be scored from the formula. Their scores encode design intent but not mathematical derivation.
→ Mitigation: each manual score records its rationale so playtesting feedback can be evaluated against that intent, not just the number.

**AoE frequency assumption (50%) may be wrong.**
The charges multiplier dampening and the AoE / `+1 target` scope modifiers all rest on the assumption that roughly half of combat encounters feature multiple enemies. If floor design skews toward single-enemy fights, AoE and arc weapons are overvalued by the formula.
→ Mitigation: tracked as a known assumption in `LLD-IR-005`. Revisit once Floor 3 encounter distribution is locked.

## Open Questions

- **Lucky Paw score**: Currently set to 18 (manual). Actual value depends on the physical evasion % once confirmed — may need to be raised significantly. `[OPEN·MVP3]`
- **HP conversion bucket amounts**: Thresholds defined in `LLD-IR-009`; HP amounts remain `[OPEN]` pending vessel HP pool and average incoming damage data from playtesting.
- **Poultice placement**: Scores 13 on the consumable scale — below the consumable reference (14) but kept in the elite pool on the basis that healing items score conservatively relative to their run value. Worth watching in playtesting.
